# muse

**给 AI 的灵感旁路。** 它不生成答案，它生成「逼你想别的」的问题。

## 为什么需要它

模型默认会收敛到最可能的答案——离问题最近的那条路。灵感恰恰来自远的那条。这个工具做的事，就是把取样强行拉远。

## 四条机制

1. **远域属性重组**：不扰动向量（要模型和向量库），扰动抽象标签——克制、失重、慢张力、不可逆。抽象才能跨域搬运。
2. **四个碰撞算子**：类比迁移 / 矛盾缝合 / 降维抽象 / 反转因果。每个都能用一句话逼出非默认解。
3. **收窄**：发散只做一轮，第二轮强制问「哪条约束是真的」——收窄比发散难，也更值钱。
4. **可验证代理**：一个想法如果写不成可证伪的预测，就不算灵感，只算话术。

## 用法

```bash
python muse2.py "AI 工具总是太具体，怎么让它产生新奇的用途"
python muse2.py "..." --json
```

输出示例（属性 延迟 / 克制，远域 音乐对位）：

```
[类比迁移] 把音乐对位的结构（主题变奏、休止、转调）当成解法骨架，
           问题变成：延迟 在这个结构里对应什么？
[矛盾缝合] 同时满足「要 延迟」和「要 克制」，怎么让它们共存？
[降维抽象] 剥掉业务细节，只留「延迟」，从零重建是什么形态？
[反转因果] 如果延迟不是结果而是原因，谁在制造它？
```

## 设计上的两条纪律

**确定性**：同一个问题永远得到同一组提示。不可复现的灵感没法检验，也没法 A/B。

**不自评**：工具本身不给创意打分。打分需要外部参照，让生成它的模型自己阅卷，是这类系统最常见的死法。所以最后一步换成了可证伪性检查。

## 局限

- 不会让模型知道它没见过的信息，只改变取样方向
- 属性标签和远域表是手工维护的，覆盖面有限
- 最后一个判断——哪个想法值得追——仍然要人或强模型来做

## 测试

6 个：确定性、不同问题不同结果、四个算子齐全、属性不重复、收窄与可验证不缺、CLI JSON 往返。
